02 / CORE METHODS

Masking & Capping Logic

Two deterministic transformations define the core data preparation strategy.
02
A
STRATEGY A / MASKING

Stratified 20% Masking

Each corrected recommendation class contributes 20% of its labeled train rows to the artificial pseudo-unlabeled pool.

masked_count = floor(0.20 × class_count)
rounding = Decimal
selection = smallest (hash, id)

Rows with NULL step1_rec_label never enter the pseudo pool.

Why this order?
Corrected labels → mask → cap. This follows the project author's documented decision.
B
STRATEGY B / CAPPING

Per-Pool Duplicate Cap

Bodies exceeding the maximum frequency are ranked independently within each pool.

MAX_COPIES_PER_BODY = 50
ORDER BY hash, id
rank > 50 → cap_dropped_*

Supervised and pseudo-unlabeled pools have separate 50-copy limits.

Why cap after masking?
Capping first could retain rows that would later be masked, disproportionately reducing the supervised pool.

04 / PROJECT PROTOCOL

Key Design Decisions

These decisions govern reproducibility, dataset construction, and data integrity.
04
D / 01

Correct Before Mask

Use corrected labels: step1_rec_label and step1_rate_band_label. Raw labels are retained for comparison.

D / 02

Mask Labeled Train Only

Rows with NULL recommendation labels never enter the artificial pseudo pool.

D / 03

Mask Before Cap

The order is deliberate: correct labels → mask → cap.

D / 04

50 Copies Per Body

The maximum is applied separately to supervised and pseudo pools.

D / 05

Single Database Table

Roles are stored in a new clean_base.train_role column. No new tables are created.

D / 06

Validation & Test Isolation

Neither split is masked, capped, or assigned a train_role value.

D / 07

Transparent Decisions

Instructor confirmation was not requested. The manifest documents the author's decision.

D / 08

Repository Numbering

Notebooks retain repository numbering. README maps them to required project names.

DETERMINISTIC SELECTION

Hash-based row selection

SQL_HASH = substr(sha256('|' || id), 1, 16)

Fixed-width lowercase hexadecimal strings are compared lexicographically. The order matches numeric order and avoids signed BIGINT overflow. ID is the tie-breaker.

07 / LIMITATIONS & TRANSPARENCY

Caveats & Next-Phase Implications

These findings should remain visible when reporting or evaluating the next phase.
07
CAVEAT / 01
Deviation from the shared protocol

Corrected labels were used before masking. This differs from the shared protocol. The resulting mask differs from the raw-label mask by only 16 IDs out of 736,316.

CAVEAT / 02
Mild Step 1 label leakage

The Step 1 majority table was built using all labeled train rows, including rows later moved into the pseudo pool. Approximately 0.3% of rows are affected.

CAVEAT / 03
Class distribution shift

The cap reduces the recommended class share in the supervised pool from 79.48% to 76.69%. Compute class weights on supervised data after capping. Macro F1 is the main metric.

CAVEAT / 04
Natural and artificial pools differ

Natural unlabeled data is not distributed like labeled or artificial pseudo-unlabeled data. Report statistics for the two pools separately.

CAVEAT / 05
Duplicated bodies can inflate pseudo accuracy

After capping, 25.32% of pseudo rows share a body with supervised rows. Report accuracy and acceptance rate both on the whole pool and on non-duplicated bodies.

CAVEAT / 06
Instructor confirmation not requested

The order of operations and the duplicate cap were decided by the project author. The manifest records this explicitly.
